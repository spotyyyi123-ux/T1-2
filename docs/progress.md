# Точка продолжения

Текущая задача: реорганизация файлов по папкам после завершения этапа 1.
Утверждённые таблицы/столбцы БД не менять; новые метаданные допускаются в существующем JSONB.

До начала этапа: единый формат данных завершён, 24 Python-теста и JS-проверки проходят.

План этапа:

1. Разбивать весь извлечённый текст на ограниченные части с перекрытием и координатами.
2. Сохранять порядок абзацев/таблиц DOCX и обозначения страниц PDF.
3. Последовательно анализировать все части, ограничить число запросов и повторы.
4. Объединять результаты без суммирования цен и произвольного выбора конфликтов.
5. Сохранять прогресс в существующих логах; сбой части означает ошибку всего анализа.
6. Проверить длинный текст, хвост документа, конфликты, сбои, удаление во время обработки.

Статус: этап 1 завершён. 44 Python-теста и JS-проверки проходят; синтаксис Python проверен.

Реализовано:

- `app/services/document_processing.py`: разбиение всего текста, ограниченные повторы запросов,
  консервативное объединение, сохранение конфликтов и метаданных покрытия.
- `app/services/text_extraction.py`: страницы PDF, порядок абзацев/таблиц DOCX, вложенные таблицы,
  существующие колонтитулы.
- `app/routers/documents.py`: новый конвейер, логи прогресса, понятные ошибки частей,
  отмена между частями при удалении документа, запись итога только после успеха.
- `app/core/settings.py`: размер части/перекрытие/максимум частей, без изменения `.env`.
- `app/services/extraction_format.py`: сохранение метаданных `processing` при чтении старых/новых результатов.
- `tests/test_document_processing.py`, дополнительные интеграционные тесты в `tests/test_library.py`.

Описание: `docs/full-document-processing.md`. UI не менялся: конфликты отображаются
через ранее добавленные пометки, прогресс — в истории обработки в «Подробнее».
Реальные запросы к LLM и запись в рабочую БД не выполнялись. Старые документы для
нового анализа нужно загрузить повторно. Точность модели ещё не измерена.
