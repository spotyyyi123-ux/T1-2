# API Contract — Contract Intelligence

Соглашение о HTTP-запросах и формате JSON между бэкендом и фронтендом.
Описывает текущую реализацию в `app/routers/`, а не проектируемые методы.

## 1. Общие правила

- Базовый путь API: `/api`. Локальный адрес: `http://127.0.0.1:8000`.
- Все методы документов и папок требуют заголовок `Authorization: Bearer <access_token>`.
- Пользователь работает только со своими документами и папками.
- JSON-запросы отправляются с `Content-Type: application/json`; загрузка — `multipart/form-data`.
- `id` пользователя и документа — целые числа, а не UUID.
- `folder_id` — строка, сгенерированная из UUID (32 шестнадцатеричных символа), либо `null`.
- В JSON используются машинные значения; готовый текст для интерфейса возвращается в `display_data`.
- Swagger UI: `/docs`; схема OpenAPI: `/openapi.json`. Форматы динамических ответов
  реестра подробно описаны ниже, поскольку не все они заданы моделями OpenAPI.

## 2. Вход / регистрация

### POST /api/users/auth

Если email уже существует, проверяется пароль; иначе создаётся пользователь.
Авторизация для этого запроса не требуется.

Тело запроса:

```json
{
  "email": "demo@example.com",
  "password": "example-password"
}
```

Успешный ответ — `200 OK` как для входа, так и для регистрации:

```json
{
  "id": 1,
  "email": "demo@example.com",
  "access_token": "<JWT>",
  "token_type": "bearer"
}
```

Ошибки: `401` — неверный пароль, `422` — невалидное тело/email,
`503` — не настроен секрет авторизации. Истёкший токен требует повторного входа;
отдельного refresh-метода нет.

## 3. Загрузка договора

### POST /api/documents/upload

Поля формы:

| Поле | Тип | Обязательность |
|---|---|---|
| `file` | файл PDF/DOCX | Обязательно |
| `folder_id` | строка | Необязательно; если отсутствует, документ будет без папки |

Пример для терминала (токен предварительно задаётся в переменной `ACCESS_TOKEN`):

```sh
curl -X POST http://127.0.0.1:8000/api/documents/upload \
  -H "Authorization: Bearer $ACCESS_TOKEN" \
  -F "file=@dataset/docx/contract_0001.docx"
```

При отправке `FormData` браузером не нужно вручную устанавливать `Content-Type`:
браузер добавит multipart boundary.

Успешный ответ — `202 Accepted`:

```json
{
  "status": "success",
  "message": "Файл загружен и отправлен в очередь на обработку",
  "document_id": 9
}
```

Это подтверждение приёма, **не успешного извлечения**. Анализ выполняется в фоне.
Статус и результат фронтенд получает обновлением реестра.

По умолчанию максимальный размер — 20 МиБ (`MAX_UPLOAD_BYTES`). Нужен текстовый слой;
OCR не выполняется. Ошибки загрузки: `400` — неподдерживаемый формат/неверная сигнатура,
`401` — нет доступа, `404` — папка не найдена, `413` — превышен размер, `422` — нет файла.
Ошибка ИИ после ответа `202` отражается в статусе `failed` и `logs`, а не меняет ответ загрузки.

## 4. Реестр и подробности договора

### GET /api/documents

Возвращает JSON-массив документов текущего пользователя, по `id` от новых к старым.
Пустой реестр — `[]`. Обёртки `total`/`documents` и серверной пагинации нет.
Поиск, сортировка и фильтрация по папке сейчас выполняются во фронтенде.

Пример ответа `200 OK` для завершённого анализа (значения демонстрационные):

```json
[
  {
    "id": 9,
    "filename": "contract.docx",
    "status": "completed",
    "folder_id": null,
    "uploaded_at": "2026-09-21T10:00:00",
    "extracted_data": {
      "contract_number": "001/26",
      "contract_date": "2026-09-20",
      "subject": "Поставка оборудования",
      "customer": "ООО «Заказчик»",
      "contractor": "ООО «Поставщик»",
      "amount": 1250000.50,
      "currency": "RUB",
      "vat_rate": "20%",
      "payment_terms": null,
      "performance_deadline": "30 дней после оплаты",
      "validity_period": "2026-12-31",
      "penalty_terms": null,
      "termination_terms": null,
      "format_version": 2,
      "unparsed_values": {},
      "processing": {
        "version": 1,
        "text_chars": 500,
        "chunks_total": 1,
        "chunks_completed": 1,
        "chunks": [{"start": 0, "end": 500, "locations": ["Абзац 1"]}]
      }
    },
    "display_data": {
      "contract_number": "001/26",
      "contract_date": "20.09.2026",
      "subject": "Поставка оборудования",
      "customer": "ООО «Заказчик»",
      "contractor": "ООО «Поставщик»",
      "amount": "1 250 000,50",
      "currency": "RUB",
      "vat_rate": "20%",
      "payment_terms": "Не найдено",
      "performance_deadline": "30 дней после оплаты",
      "validity_period": "31.12.2026",
      "penalty_terms": "Не найдено",
      "termination_terms": "Не найдено"
    },
    "logs": [
      "Файл загружен, ожидает обработки",
      "Документ разбит на 1 частей. Начат полный анализ",
      "Обработано частей: 1/1",
      "Анализ всех частей успешно завершён"
    ]
  }
]
```

`uploaded_at` — ISO-строка времени загрузки; существующие значения без часового
пояса интерпретируются как UTC. `logs` — массив сообщений, не структурированных событий;
клиенту не следует использовать их формулировки как стабильные коды ошибок.
У документа без результата `extracted_data` и `display_data` равны `null`.
У старых результатов `processing` может отсутствовать.

**Отдельного `GET /api/documents/{document_id}` пока нет.** Окно «Подробнее» использует
объект из реестра. API не возвращает `raw_text`, путь к файлу, ИНН или массив `parties`.
Эти поля из исходного примера контракта не являются реализованными возможностями.

### Статусы документа

| Статус | Значение |
|---|---|
| `pending` | Файл принят и ожидает обработки |
| `processing` | Анализ выполняется |
| `completed` | Все части обработаны; некоторые поля всё ещё могут требовать проверки |
| `failed` | Анализ завершился ошибкой; частичный результат не считается успешным |

`status: "success"` в ответах операций не является статусом документа.

### Формат извлечённых полей

| Поле | Тип / правило |
|---|---|
| `contract_number` | строка или `null`; ведущие нули сохраняются |
| `contract_date` | календарная дата `YYYY-MM-DD` или `null` |
| `customer`, `contractor` | названия сторон: строка или `null` |
| `amount` | JSON-число с точностью до двух дробных знаков или `null`, не обязательно integer |
| `currency` | трёхбуквенный код в верхнем регистре или `null` |
| Остальные основные поля | строки или `null`; точные одиночные даты в сроках нормализуются в ISO |
| `unparsed_values` | объект `поле: исходное значение/описание конфликта` для ручной проверки |
| `format_version` | целое число, сейчас `2` |
| `processing` | необязательные метаданные обработки полного текста |

Пропуск — `null`, а не ноль или строка `"Не найдено"`. Сумма и дата для показа берутся
из `display_data`; символ валюты добавляет интерфейс. Для вычислений используйте
десятичную арифметику: обычный JavaScript `Number` может потерять точность больших сумм.
Подробности: [формат данных](data-format.md), [обработка полного текста](full-document-processing.md).

## 5. Перемещение документа

### PATCH /api/documents/{document_id}/folder

JSON-тело для переноса в папку:

```json
{"folder_id": "e8eb97cc13284e5e8e43f23b0cb84fe6"}
```

Для переноса в «Без папки»: `{"folder_id": null}`.
Успешный ответ — `200 OK`:

```json
{"status": "success", "folder_id": "e8eb97cc13284e5e8e43f23b0cb84fe6"}
```

Ошибки: `401` — нет доступа, `404` — документ/папка не найдены у пользователя,
`422` — неверный формат запроса.

## 6. Удаление документа

### DELETE /api/documents/{document_id}

Удаляет запись, извлечённые данные, логи и оригинальный файл (если он не используется
другой записью). Это не перемещение в корзину. Ответ `200 OK`:

```json
{"status": "success", "cleanup_pending": false}
```

Если `cleanup_pending` равно `true`, запись уже удалена, но очистка файла или
метаданных папки не завершилась. Автоматический обработчик отложенной очистки пока
не реализован. Ошибки: `401`, `404`, `409` — путь файла вне допустимого хранилища.

## 7. Папки

### GET /api/folders

Ответ `200 OK` — массив папок пользователя (либо `[]`):

```json
[
  {
    "id": "e8eb97cc13284e5e8e43f23b0cb84fe6",
    "name": "Поставки",
    "created_at": "2026-09-21T10:00:00+00:00"
  }
]
```

### POST /api/folders

Тело: `{"name": "Поставки"}`. Ответ `201 Created` — объект папки с `id`, `name`,
`created_at`, как в примере выше.

### PATCH /api/folders/{folder_id}

Тело: `{"name": "Архив"}`. Ответ `200 OK` — обновлённый объект папки.

### DELETE /api/folders/{folder_id}

Ответ `200 OK`:

```json
{
  "status": "success",
  "message": "Папка удалена. Документы перемещены в «Без папки»."
}
```

Удаление папки не удаляет её документы. Имя папки — 1–80 символов, без `/`, `\`
и управляющих символов; пробелы нормализуются. Дубликаты имён без учёта регистра
не допускаются. Ошибки: `400` — недопустимое имя после проверки, `401` — нет доступа,
`404` — папка не найдена, `409` — дубликат, `422` — нарушение схемы тела запроса.

## 8. Формат ошибок

Контролируемые ошибки HTTP возвращают `detail`, а не `error`:

```json
{"detail": "Документ не найден"}
```

При ошибке валидации FastAPI (`422`) значение `detail` — массив описаний полей.
Непредвиденная серверная ошибка (`500`) может иметь не-JSON тело: фронтенд должен
проверять HTTP-статус и обрабатывать невозможность разобрать JSON.

## 9. Отличия от исходного примера

Присланный пример использован как образец структуры документа. В текущем API:
`/api/documents/upload` вместо `/upload`, ответ загрузки `202` вместо `201`,
целочисленные ID вместо UUID документов, массив реестра вместо объекта с `total`,
`contract_number`/`contract_date`/`contractor` вместо `number`/`date`/`executor`.
Изменение документации не добавляет новые методы и не меняет схему БД.
