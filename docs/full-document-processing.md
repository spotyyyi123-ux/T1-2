# Обработка полного извлечённого текста

## Порядок работы

1. `app/services/text_extraction.py` извлекает текстовый слой PDF с номерами страниц. Для DOCX
   сохраняется порядок абзацев и таблиц, включая вложенные таблицы; добавляются
   существующие колонтитулы. Пустые блоки не становятся фиктивным текстом.
2. `app.services.document_processing.split_text` делит весь полученный текст на части с
   перекрытием. Предпочтительны границы строк; длинный непрерывный текст также
   обрабатывается. Координаты частей позволяют проверить отсутствие пропусков.
3. Каждая часть последовательно отправляется провайдеру. При временной сетевой
   ошибке, HTTP 408/429/5xx разрешён один повтор через секунду. Ошибки авторизации,
   некорректный JSON и обрезанный ответ провайдера не считаются успешной обработкой.
4. Результаты нормализуются и объединяются. Одинаковые значения не суммируются;
   разные значения одного поля сохраняются в `unparsed_values` с номерами частей,
   само поле становится `null`. Неоднозначность, заявленная провайдером внутри
   одной части через `uncertain_fields`, также сохраняется для проверки.
5. Итог записывается в существующий JSONB только после успеха всех частей.
   При сбое любой части статус документа — `failed`, частичного результата нет.

Прогресс `Обработано частей: N/M` виден в истории обработки в «Подробнее».
Удаление документа прерывает дальнейшую обработку на ближайшей проверке прогресса;
уже отправленный запрос может завершиться и быть оплачен, но результат не создаст
удалённый документ заново.

## Ограничения запросов

По умолчанию дополнительных настроек не требуется:

```dotenv
MAX_PROMPT_CHARS=12000
CHUNK_OVERLAP_CHARS=800
MAX_DOCUMENT_CHUNKS=40
```

`MAX_PROMPT_CHARS` теперь ограничивает **одну часть**, а не весь документ.
Перекрытие должно быть неотрицательным и меньше половины размера части.
Число частей должно быть положительным. Проверка лимита выполняется до запросов
к провайдеру. Если документ не помещается, выдаётся ошибка с предложением разделить
файл или увеличить лимит; молчаливого обрезания нет.

Обычная обработка: один запрос на часть; с повторами — максимум два.
Поэтому длинные договоры требуют больше времени и средств на API. Ключи и настройки
в `.env` автоматически не изменяются.

## Метаданные

В JSONB и ответе API у новых результатов есть `processing`:

- `version`: версия конвейера, сейчас 1;
- `text_chars`: длина извлечённого текста с метками;
- `chunks_total`, `chunks_completed`: плановое и обработанное число частей;
- `chunks`: смещения `start`/`end` (конец не включён) и метки расположения `locations`.

Это сведения о покрытии текста, **не доказательство происхождения каждого значения**.
Кликабельные цитаты-источники — отдельный будущий этап.

Существующие таблицы и столбцы БД не меняются. Ранее сохранённые документы не
пересчитываются: для нового анализа файл нужно загрузить повторно.

## Что не гарантируется

- Полностью обрабатывается текст, извлечённый библиотеками, а не изображение документа.
  OCR, сканы, изображения текста, сложные графические объекты DOCX и сложная вёрстка
  PDF могут требовать отдельного извлечения; это не обещание распознать любой файл.
- Независимые фрагменты могут не содержать контекста, необходимого для вывода.
  Полнота отправки не равна точности извлечения. Противоречия и даже разные формулировки
  условий намеренно отправляются на проверку, а не разрешаются догадкой.
- Обработка пока выполняется через FastAPI BackgroundTasks, без устойчивой очереди.
  Перезапуск сервера не возобновляет незавершённое задание автоматически.
- Автотесты используют подмену провайдера и временную SQLite-БД, а не платные
  запросы и рабочий PostgreSQL. Точность реальной модели нужно измерить на эталонах.

## Проверки

```sh
python -m unittest discover -s tests -v
node tests/test_registry.js
```

Регрессии: покрытие каждого символа, конец текста длиннее старого лимита,
нормализация/конфликты, локальная неоднозначность, лимиты до запросов, повторы,
ошибки середины обработки, прогресс, отсутствие частичной записи, отмена при
удалении, порядок DOCX и номера страниц PDF.
