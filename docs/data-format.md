# Формат результатов извлечения

Таблицы, столбцы и связи БД не меняются. Новые результаты записываются в существующий
JSONB `extracted_data`. Старые записи приводятся к формату v2 при чтении API,
без перезаписи БД и повторного запроса к ИИ.

## Машинные данные

`GET /api/documents` возвращает у каждого документа `extracted_data`:

```json
{
  "contract_number": "001/26",
  "contract_date": "2026-09-20",
  "subject": "Поставка оборудования",
  "customer": "ООО «Заказчик»",
  "contractor": "ООО «Поставщик»",
  "amount": 1250000.50,
  "currency": "RUB",
  "vat_rate": "20%",
  "payment_terms": null,
  "performance_deadline": "30 дней после оплаты",
  "validity_period": "2026-12-31",
  "penalty_terms": null,
  "termination_terms": null,
  "format_version": 2,
  "unparsed_values": {}
}
```

- `contract_number`: строка, сохраняющая ведущие нули.
- `contract_date`: существующая календарная дата `YYYY-MM-DD` либо `null`.
- `amount`: JSON-число без разделителей тысяч и валюты либо `null`. В Python
  используется `Decimal`; сериализация HTTP и JSONB сохраняет десятичную точность.
  Поддерживаются суммы с точностью до двух десятичных знаков. Округление не выполняется.
- `currency`: трёхбуквенный код в верхнем регистре либо `null`; рубли по умолчанию
  не подставляются. Если отдельного кода нет, он может быть извлечён из записи суммы.
- `performance_deadline`, `validity_period`: полная одиночная дата приводится к ISO;
  относительные сроки, диапазоны и условия остаются текстом.
- Остальные поля: строки либо `null`. Массивы/словари старых текстовых полей
  преобразуются в читаемый текст; старые `number`, `date`, `parties` поддерживаются.
- Отсутствующие значения во всех основных полях — `null`, не `"Не найдено"` и не ноль.

Неоднозначная сумма (`"1.234"`, диапазон, формула), число с лишними значащими
дробными знаками (`1.234`) или невозможная дата не превращаются в догадку:
основное поле равно `null`, исходное значение сохраняется текстом в `unparsed_values`.
Число `1.2300` допустимо и равно `1.23`; строка `"1 234"` однозначно означает `1234`.

Нормализация проверяет формат, но **не доказывает правильность извлечения из договора**.
Для измерения точности нужен отдельный набор эталонных ответов.

Новый конвейер дополнительно сохраняет метаданные `processing` и заносит в
`unparsed_values` конфликты между частями. Подробности — в
[описании обработки полного текста](full-document-processing.md).

## Отображение

API дополнительно возвращает `display_data` с теми же 13 основными полями для
интерфейса: `20.09.2026`, `1 250 000,50`, `Не найдено`. К сумме UI добавляет валюту
одинаково в реестре и подробностях. Нераспознанные значения сопровождаются
пометкой «нужна проверка».

`display_data` вычисляется на сервере и отдельно в БД не сохраняется. Для сортировки
денег интерфейс использует точную строку отображения и `BigInt`, чтобы стандартный
JavaScript `Number` не терял копейки у больших сумм. Другим API-клиентам также
нужен десятичный JSON-парсер, если важна точность больших денежных значений.

## Проверка

```sh
python -m pip install -r requirements.txt
python -m unittest discover -s tests -v
node tests/test_registry.js
```

Тесты используют временную SQLite-БД с тестовым отображением JSONB и не изменяют
рабочие записи PostgreSQL. Проверяются старый/новый формат, точность денег,
сохранение и HTTP-ответ, невалидные даты, пропуски, поиск и сортировка.
